Inexo ERP: one platform for very different businesses

Python, PostgreSQL, JavaScript, Docker, AWS

Problem
A machine builder, a gas distributor and an HR team all needed the same product to fit how they work, without a separate codebase for each.
Challenge
The core was tightly coupled around a single class of roughly 8,000 lines, so every client change risked breaking the others.
What I did
Broke the core into maintainable modules while clients stayed live, built the branded product with client-specific editions on one shared core, and extended workflows across manufacturing, HRMS, inventory, procurement, accounting and sales. I also run discovery and demos with prospects.
Outcome
One maintainable platform serving several industries, and 20+ prospects supported through to signed clients.

Cloud architecture: isolated, cheaper, easier to run

AWS, private VPS, Docker, Linux, Nginx, PostgreSQL

Problem
Hosting every client on managed AWS services was expensive, and clients needed clean separation from each other.
What I did
Gave each client its own Docker environment with separate production and UAT, SSL, Git-based deployments and PostgreSQL backups. Moved the platform from AWS to private VPS servers in about a week, and designed an agent-based control plane for managing client environments without direct SSH.
Outcome
Infrastructure costs down by roughly 25 to 50%, a result shared with the wider team.

Inexo AI: asking the ERP in plain language

Proof of concept, still being built

Problem
Business owners wanted quick answers on stock, pending orders or payroll without waiting for someone to pull a report.
Approach
Qwen3-4B connected to the ERP through our own MCP server, with an intelligence layer on top: retrieval over the client's records and documentation, an orchestrator that routes each request to the right tool, role-based permissions, and a confirmation step before anything is written.
Status
Working end to end internally and being built out toward production.
